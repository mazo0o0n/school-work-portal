# قائمة الجاهزية القانونية والخصوصية

آخر مراجعة داخلية: 27 يوليو 2026.

> هذه الوثيقة مساعدة داخلية تقنية وليست استشارة قانونية ولا بديلًا عن مراجعة محامٍ أو مختص امتثال سعودي قبل البيع أو الاشتراكات أو توسيع جمع البيانات.

## البيانات التي يجمعها أو يعالجها المشروع حاليًا

| الفئة | أمثلة حالية | التصنيف الحذر |
|---|---|---|
| ملف المدرسة | اسم المدرسة، المرحلة، إدارة التعليم، المعرّف العام، حالة التحقق | بيانات منشأة، وقد تصبح قابلة للربط بأشخاص أو موقع عمل |
| رمز التعديل | قيمة تصدر عند التسجيل وتحفظ محليًا، بينما يخزن الخادم مشتقها | بيانات اعتماد حساسة يجب حمايتها كسر |
| إعدادات التقارير | الرقم الوزاري وأسماء مدير المدرسة والوكلاء ورائد النشاط عند إدخالها | الرقم معرّف مؤسسي؛ أسماء الموظفين بيانات شخصية |
| إعدادات الواجهة | المظهر، حالة الأقسام، وضع الضيف، تفضيلات التقارير | بيانات تفضيل منخفضة الحساسية غالبًا |
| محادثة المساعد | نص السؤال والرد داخل جلسة المتصفح | قد يحتوي بيانات شخصية إذا أدخلها المستخدم |
| الأسئلة غير المجابة | نسخة معقمة من السؤال، سبب fallback، الصفحة، الحالة، التكرار، التواريخ | محتوى مستخدم يحتمل بقايا بيانات شخصية رغم التعقيم |
| سجل التدقيق | العملية، نوع الكيان، معرف المدرسة، النتيجة، تغير الحالة، الوقت | بيانات تشغيل إدارية؛ لا يتضمن اسم المدرسة في التصميم الحالي |
| بيانات تشغيل المنصة | طلبات وأخطاء ومقاييس توفرها منصة الاستضافة حسب الإعداد | النطاق الفعلي يحتاج مراجعة إعدادات Cloudflare وعقودها |

لا يجمع المشروع حاليًا، حسب الكود الذي تمت مراجعته، بيانات طلاب أو سجلات درجات كجزء من التسجيل الأساسي. بعض الأدوات المحلية قد تعالج ملفات يختارها المستخدم في المتصفح؛ يجب التحقق بصورة مستقلة من بقائها محلية قبل تقديم ضمان تجاري.

## أين تخزن البيانات

### `localStorage`

- ملف المدرسة المحلي واسم العرض والمرحلة وإدارة التعليم.
- المعرّف العام ورمز التعديل الصادر عند التسجيل.
- إعدادات المظهر ووضع الضيف وحالة بعض الأقسام.
- تفضيلات بيانات تقارير المدير، وقد تتضمن أسماء موظفين ورقمًا وزاريًا.

يبقى التخزين حتى يمسحه المستخدم أو التطبيق أو المتصفح. لا توجد حاليًا مدة انتهاء موحدة لكل المفاتيح.

### `sessionStorage`

- محادثة مساعد المنصة ضمن الجلسة، وحالة فتح اللوحة.
- بعض قيم الاستخدام المرحلية التي تزول عادة بانتهاء جلسة المتصفح.

### D1: جدول `schools`

- اسم المدرسة، المرحلة، إدارة التعليم، المعرّف العام، مشتق رمز التعديل، حالة التحقق، وتواريخ الإنشاء والتحديث.

### D1: جدول `unanswered_questions`

- السؤال المعقم، النسخة الطبيعية للمقارنة، السبب، مسار الصفحة، المصدر، الحالة، عدد التكرار، والتواريخ. دعم الأرشفة مجهز في migration منفصلة ويحتاج قرار تطبيق مستقل.

### D1: جدول `audit_logs`

- أحداث تغيير حالة المدرسة وحذفها، معرف الكيان، النتيجة، metadata حالة مختصرة، ووقت العملية.

## فجوات ومخاطر الخصوصية

1. **عدم تطابق السياسة المنشورة:** صفحة الخصوصية الحالية تذكر أن بيانات المدرسة المحلية لا تُرسل إلى طرف خارجي، بينما التسجيل الحالي يرسل اسم المدرسة والمرحلة وإدارة التعليم إلى `/api/schools/register` لتخزينها في D1. يجب تصحيح النص قبل أي عرض تجاري.
2. أسماء الموظفين في إعدادات التقارير بيانات شخصية حتى لو بقيت محليًا؛ يجب توضيح الغرض والمسؤولية ومدة الاحتفاظ.
3. رمز تعديل المدرسة مخزن في المتصفح؛ يجب توضيح أثر مسح الجهاز أو مشاركته، وتقييم استبداله بجلسات وحسابات في SaaS.
4. التعقيم يقلل خطر الأسئلة غير المجابة لكنه لا يضمن إزالة كل معلومة حساسة أو سياقية.
5. لا توجد واجهة مكتملة لطلب الوصول أو التصحيح أو الحذف أو تصدير البيانات.
6. لا توجد مدة احتفاظ مطبقة آليًا لكل فئة.
7. لا توجد موافقة أو إشعار تفصيلي للقياسات المستقبلية؛ يجب ألا يضاف analytics قبل تحديد الأساس والغرض.
8. موقع المعالجة الفعلي والنسخ الاحتياطية والاحتفاظ في Cloudflare يحتاج مراجعة إعدادات الحساب والعقد، وليس الاستنتاج من الكود.

## متطلبات سياسة الخصوصية

- تحديد هوية المشغل ووسيلة التواصل الرسمية المعتمدة.
- وصف دقيق لكل بيانات تُجمع عند التسجيل والمساعد والإدارة والتقارير.
- الغرض من المعالجة والأساس النظامي الذي يحدده المستشار القانوني.
- مواقع وفئات التخزين ومقدمي الخدمة والحدود الجغرافية الفعلية.
- مدد الاحتفاظ أو معايير تحديدها.
- حقوق صاحب البيانات وآلية الطلب والتحقق والاستجابة.
- سياسة الأطفال والطلاب إن تغير النطاق مستقبلًا.
- الإفصاح عن النقل أو المعالجة لدى مزودي الخدمات.
- إجراءات الحوادث والتحديثات الجوهرية للسياسة.
- تاريخ النفاذ وسجل تحديث واضح.

## متطلبات سياسة الاستخدام

- المنصة مساعدة وليست جهة رسمية أو بديلًا عن الأنظمة والتعاميم.
- مسؤولية المستخدم عن مراجعة تقارير Word قبل اعتمادها.
- منع إدخال كلمات المرور والهواتف والهويات وبيانات الطلاب في المساعد.
- شروط استخدام الشعارات والقوالب والروابط الخارجية.
- حدود الخدمة والتوفر والدعم والمسؤولية عن تغير الموارد الخارجية.
- آلية تعليق الوصول أو إساءة الاستخدام مستقبلًا.
- شروط الملكية الفكرية والترخيص عند اعتماد نموذج البيع.

## ملاحظات PDPL السعودية

- قد تنطبق متطلبات نظام حماية البيانات الشخصية السعودي ولائحته بحسب هوية المشغل، نوع البيانات، مكان المعالجة، والغرض والعلاقة مع المدارس.
- أسماء الموظفين ومحتوى الأسئلة قد تكون بيانات شخصية، حتى إذا لم تُجمع هوية وطنية أو هاتف.
- تقليل البيانات، تحديد الغرض، الشفافية، الأمن، الاحتفاظ المحدود، وتمكين الحقوق مبادئ يجب تحويلها إلى إجراءات قابلة للإثبات.
- نقل البيانات أو معالجتها خارج المملكة يحتاج تقييمًا قانونيًا وتعاقديًا وفق الوضع الفعلي لمناطق Cloudflare والخدمات المستخدمة.
- لا يمكن لهذه الوثيقة تحديد الأساس النظامي أو صفة المتحكم والمعالج أو مشروعية النقل؛ يلزم مختص قانوني.

## بيانات لا يجب جمعها دون حاجة وموافقة معتمدة

- الهوية الوطنية أو الإقامة.
- كلمات المرور أو رموز الدخول أو مفاتيح API.
- أرقام الحسابات أو بيانات الدفع قبل وجود مسار فوترة معتمد.
- بيانات الطلاب والدرجات والسلوك والصحة والاحتياجات الخاصة.
- هواتف وبريد الموظفين أو أولياء الأمور لمجرد التحليل.
- IP خام أو بصمة جهاز أو موقع دقيق لأغراض قياس عامة.
- نصوص كاملة لأسئلة المساعد ضمن analytics.
- نسخ من قوالب أو ملفات تحتوي بيانات أشخاص حقيقية.

## مدد احتفاظ مقترحة للمراجعة

هذه المدد مقترحات تشغيلية وليست سياسة معتمدة:

| الفئة | المدة المقترحة | الإجراء |
|---|---|---|
| ملف مدرسة نشط | طوال تقديم الخدمة مع مراجعة سنوية | حذف أو إخفاء الهوية بعد انتهاء العلاقة ومدة تسوية معتمدة |
| طلب تسجيل غير متحقق | 90 يومًا | حذف أو إعادة طلب التحقق إذا لم توجد حاجة تشغيلية |
| الأسئلة غير المجابة الجديدة | 90 يومًا | مراجعة ثم أرشفة أو حذف المحتوى غير المفيد |
| الأسئلة المؤرشفة/المجمعة | حتى 180 يومًا | الاحتفاظ بالعداد المجمع وحذف النص عند عدم الحاجة |
| سجل التدقيق الإداري | 12 شهرًا | حذف دوري أو تمديد بسبب التزام موثق |
| محادثة الجلسة | حتى إغلاق الجلسة | لا تنقل إلى تخزين دائم دون إشعار جديد |
| سجلات أخطاء تشغيلية | 30–90 يومًا | إزالة أو تعمية المعرفات وتقليل الوصول |

## سياسة حذف مقترحة

1. توفير قناة موثقة لطلب حذف ملف المدرسة أو تصحيحه.
2. التحقق من سلطة مقدم الطلب دون طلب بيانات أكثر من اللازم.
3. تحديد أثر الحذف على سجل التدقيق والنسخ الاحتياطية والمتطلبات النظامية.
4. حذف البيانات النشطة، ثم وضع جدول زمني لانتهاء النسخ الاحتياطية.
5. تسجيل تنفيذ الطلب دون الاحتفاظ بالمحتوى المحذوف.
6. توفير تأكيد للمستخدم ومدة استجابة معلنة.
7. عدم استخدام الحذف المباشر في لوحة الإدارة كبديل عن عملية حقوق بيانات موثقة.

## Cloudflare وموضع الاستضافة

المشروع يستخدم خدمات Cloudflare في التشغيل الحالي. لا تكفي ملفات المستودع لتحديد منطقة التخزين الفعلية، مسارات النسخ الاحتياطي، مدد السجلات، أو شروط النقل الدولي. قبل البيع يجب مراجعة إعدادات الحساب والخطة واتفاقية معالجة البيانات ومواقع الخدمات الفعلية، وتوثيق النتيجة دون نشر تفاصيل حساسة.

## درجة جاهزية الخصوصية

**4 من 10.**

توجد ضوابط تقنية جيدة نسبيًا مثل تعقيم الأسئلة، تقليل سجل التدقيق، وحماية الإدارة، لكن السياسة المنشورة لا تطابق التسجيل الحالي بالكامل، ولا توجد مدد احتفاظ أو حقوق مستخدم أو مراجعة قانونية معتمدة. الأولوية هي تصحيح الشفافية، تحديد المالك والغرض، وإغلاق سجل البيانات والاحتفاظ والحذف قبل البيع.
