# دليل التشغيل والإدارة

هذا الدليل يوضح ترتيب المراجعة والنشر وإدارة لوحة المدارس وتقارير المدير. لا يحتوي على قيم أسرار، ولا ينفذ أي خطوة تلقائيًا.

## ترتيب النشر الصحيح

1. تحقق من الفرع وحالة Git باستخدام `git status --short` وراجع الفرق المراد نشره.
2. شغّل `npm run qa` وتأكد من نجاح جميع بوابات الجودة.
3. تحقق من وجود أسماء الأسرار المطلوبة في بيئة Cloudflare دون طباعة قيمها:
   - `ADMIN_API_TOKEN`
   - `RATE_LIMIT_SALT`
4. راجع migrations الجديدة. إذا وُجدت migration معتمدة، خذ نسخة احتياطية مناسبة وافحص البيانات أولًا، ثم طبّق migration قبل نشر الكود الذي يعتمد عليها.
5. نفّذ deploy فقط بعد موافقة صريحة وبعد نجاح الخطوات السابقة.
6. اختبر الإنتاج: الصفحات العامة، التسجيل، المساعد، لوحة الإدارة، تنزيل تقرير Word، وأخطاء Console والشبكة.
7. أنشئ tag للإصدار بعد اعتماد نتيجة الإنتاج، وليس قبلها.

لا يُدمج deploy أو migrations أو Vectorize upsert في `npm run qa`.

## إضافة تقرير مدير

1. شغّل الواجهة المحلية من `tools/open-report-manager.bat`؛ وهي تشغّل أداة الإدارة المحلية وتفتحها في المتصفح.
2. أضف قالب DOCX وبيانات التقرير من الواجهة، ثم راجع المعاينة قبل الحفظ.
3. شغّل:

```powershell
node tools/check-manager-reports.js
node tools/check-links.js
npm run qa
```

4. اختبر التقرير في المكتبة، وراجع تعبئة الحقول وتنزيل Word على سطح المكتب والجوال.
5. يحتاج ظهور التقرير في الإنتاج إلى مراجعة الملفات، ثم commit وpush وdeploy بموافقات منفصلة. الأداة المحلية لا تنشر شيئًا تلقائيًا.

للتفاصيل الكاملة راجع `docs/manager-reports-workflow.md`.

## اختبار لوحة إدارة المدارس

1. افتح `admin-schools.html` عبر البيئة المحلية المناسبة.
2. أدخل رمز الإدارة في الحقل المخصص. يبقى الرمز في ذاكرة JavaScript للجلسة الحالية فقط، ولا يُحفظ في `localStorage` أو `sessionStorage`.
3. تحقق من الإحصاءات والبحث والتصفية والتنقل بين الصفحات.
4. غيّر حالة مدرسة اختبار وتأكد من ظهور العملية في سجل العمليات الإدارية.
5. افتح نافذة حذف مدرسة اختبار، وراجع الاسم والمرحلة وإدارة التعليم، ثم اكتب كلمة `حذف` للتأكيد.
6. تحقق من تسجيل الحذف في سجل العمليات وعدم ظهور أسرار أو بيانات غير لازمة.
7. سجّل الخروج وتأكد من اختفاء البيانات وتوقف التحديث التلقائي وتفريغ رمز الإدارة.
8. أعد الاختبار على عرض 390×844 وتأكد من عدم وجود تمرير أفقي أو أخطاء Console.

جميع مسارات `/api/admin/schools` ومسار `/api/admin/audit-logs` تتطلب header باسم `X-Admin-Token`. لا تضع قيمة الرمز في الملفات أو عناوين URL أو لقطات الشاشة أو سجلات Console.

## التعامل مع migrations

- لا تعدّل migration مطبقة؛ أضف migration جديدة ومراجعة بصورة مستقلة.
- قبل إنشاء قيد `UNIQUE` على هوية المدرسة، افحص المكررات أولًا، مثل:

```sql
SELECT
  lower(trim(school_name)) AS normalized_name,
  school_stage,
  lower(trim(education_department)) AS normalized_department,
  COUNT(*) AS duplicate_count
FROM schools
GROUP BY normalized_name, school_stage, normalized_department
HAVING COUNT(*) > 1;
```

- إذا أعاد الفحص صفوفًا، عالجها بخطة معتمدة قبل تطبيق قيد التفرد؛ لا تحذف سجلات تلقائيًا.
- راجع migration محليًا، خذ نسخة احتياطية مناسبة، ثم طبّقها على البيئة المحددة قبل deploy الذي يعتمد عليها.
- تحقق بعد التطبيق من الجداول والفهارس والمشغلات، ثم اختبر المسارات الإدارية ذات الصلة.

## فحص الجاهزية المحلي

يمكن تشغيل الفحص الآمن للقراءة فقط:

```powershell
node tools/project-readiness-check.js
```

يتحقق من وجود الملفات الأساسية، ومراجع `check:syntax`، وقواعد حجب الأصول الداخلية، ويشغّل فحص الروابط وفحص مكتبة التقارير. لا يتصل بالإنترنت ولا يطلب أسرارًا ولا يغيّر ملفات.

## حماية الإدارة مستقبلًا

المصادقة الحالية تعتمد على `ADMIN_API_TOKEN` مع تحديد محاولات الدخول. يوصى مستقبلًا بوضع صفحات ومسارات الإدارة خلف Cloudflare Access كطبقة إضافية، لكن Cloudflare Access غير مطبق من كود المشروع حاليًا ويتطلب قرار تشغيل منفصلًا.
